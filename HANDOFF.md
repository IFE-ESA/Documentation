## 1. What exists today

### Inputs (project root)
- `Documentation of IFE-TIMES-Norway v5.docx` (11 MB): source of the text and structure.
- `Documentation of IFE-TIMES-Norway v5.pdf` (6.8 MB): **authoritative**. Where it differs from the Word
  file, the PDF wins. It is also the source for the charts, EMF drawings and shape overlays, which are cropped from it.

### Main site: `docs/`
- `docs/source/` holds the generated MyST Markdown, `conf.py`, `_static/custom.css` and `images/`.
  Built output is in `docs/build/html/`; open `index.html`.
- Pages:
  - index;
  - "About this report": Summary, Authors and report information. These are unnumbered and come from the
    cover's info table, with values taken from the PDF;
  - chapters 1–7 with Sphinx numbering to 4 levels. Chapters 4 and 5 are split into one page per section;
  - Appendix A (unnumbered).
- Content:
  - 167 references, 48 figures, 92 tables;
  - per-page "References cited on this page" lists, plus the full References page;
  - a word-level check finds the body text identical to the PDF, apart from one intentional correction (see 1.4).
- `docs/requirements.txt` pins sphinx 7.4.7, sphinx-rtd-theme 3.1.0 and myst-parser 3.0.1.
  `.readthedocs.yaml` is at the root.
- `docs/conversion_report.json` records the figures, field updates, front-matter values, PDF differences and warnings.

### Mirror site: `mirror/`
- Same text and pages as the main site, but 34 data charts are redrawn in one consistent matplotlib style
  (`mirror/figures/`, with `manifest.json`, CSV data and SVG/PNG files).
- 26 charts are redrawn from the data inside the Word charts and match it exactly.
- 8 plots, plus Figure 11's second part, are digitized and therefore approximate; `manifest.json` gives the accuracy of each.
- The other 14 (diagrams, maps, schematics) are the original images.
- A validator subagent independently checked every redrawn figure and all of them pass.

### Tools
- `tools/docx2rtd.py` is the converter (Word + PDF → Sphinx). It runs again on future versions.
- `tools/restyle_figures.py` and `tools/restyle_style.mplstyle` are the figure restyling for the mirror.
- `tests/test_docx2rtd.py` and `tests/docx_variants.py`: 71 tests, all passing.
  They take about 3.5 minutes: `.venv/bin/python -m pytest tests -q`.
- `.venv/` is the local Python 3.9 venv (341 MB) and must not be committed. pandoc 3.14 is installed via Homebrew.

### Step 2: fix the mirror's Read the Docs config before publishing it
`mirror/.readthedocs.yaml` currently has paths relative to `mirror/` (`source/conf.py`), but Read the Docs
resolves them from the **repository root**. Fix:
- add a `--rtd-config <path>` option to `tools/docx2rtd.py` so it can write e.g. `mirror/.readthedocs.yaml`
  with root-relative paths (`mirror/source/conf.py`, `mirror/requirements.txt`) while `--rtd-root .` stays the repo root;
- in the second Read the Docs project, set *Admin → Settings → Path for .readthedocs.yaml* = `mirror/.readthedocs.yaml`;
- re-run the tests after the change; add a test for the new option.

### Step 3: GitHub
- The GitHub CLI isn't installed: `brew install gh`, then `! gh auth login` (interactive, run by the user).
- Create the repository and push:
  `gh repo create <owner>/<name> --public --source . --push`.
  Or create it in the web UI, then `git remote add origin …` and `git push -u origin main`.
- Optional CI (`.github/workflows/docs.yml`): on push, install `docs/requirements.txt` and run
  `sphinx-build -W` for both `docs/source` and `mirror/source`.
  - A full re-conversion job would need pandoc (`apt-get install pandoc` or a pandoc action),
    `pymupdf lxml pillow`, and the docx/pdf files in the repository.
  - Running `pytest` in CI also needs those inputs. Tests marked `needs_inputs` skip without them.

### Step 4: Read the Docs
- Sign in at readthedocs.org with GitHub, then *Import a Project* → pick the repository. It uses the root `.readthedocs.yaml`.
- Check the first build log. It uses Python 3.12 and ubuntu-24.04, and the local site was tested on Python 3.9,
  so confirm it builds cleanly.
- Optional:
  - a second project for the mirror (see Step 2);
  - a custom domain;
  - versions/tags, e.g. tag `v5` for this report version.

### Step 5: after publishing
- Add the Read the Docs badge and URLs to `README.md`.
- To publish a new report version: run `tools/docx2rtd.py` (and `tools/restyle_figures.py` for the mirror)
  as in `README.md`, check the warnings in `docs/conversion_report.json`
  (cross-reference corrections, `pdf_text_differences`), run the tests, then commit and tag.
